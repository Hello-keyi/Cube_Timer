## F8 · 批量录入（成绩 + 多条打乱）· 对应后端 D16

> 状态：⬜ 未开始（等后端 `POST /record/full`）

**目标**：一次请求提交"成绩 + 多条打乱"，理解「前端一次提交 = 后端一个事务」。

**为什么要**：D16 后端用 `@Transactional` 保证两张表原子写；前端如果还一条条 POST，就失去了事务的意义，而且失败后状态混乱。

**契约（后端 D16）**：
```
POST /record/full
body: { "timeMs": 1234, "scrambles": ["R U R'", "F2 D"] }
返回: Result<Void>  → 成功 code=0；失败 code=1 + msg（如"打乱内容过长"）
```

**学**：JSON 数组字段；表单动态增删行；提交中状态；**整体失败**提示（不是逐条）。

**做**
1. 新建页面 `/record/new`（路由 + 导航入口）
2. 表单：秒数输入 + 多条打乱（"+ 加一条 / 删除"）
3. 前端校验：秒数 > 0；每条打乱非空；条数上限（问后端）
4. `api/records.js` 加 `createRecordFull({ timeMs, scrambles })`
5. 提交成功 → 跳详情/历史并刷新；失败 → 显示 `msg`，**保留表单内容**

**代码骨架（只给结构，不写实现）**
```js
// api
export async function createRecordFull(payload) { /* POST /record/full，判 code，返回 data */ }

// 页面
const timeSec = ref('')
const scrambles = ref([''])          // 多行
const submitting = ref(false)
const errorMsg = ref('')
async function submit() { /* 校验 → submitting=true → await createRecordFull(...) → 成功跳转 / 失败写 errorMsg → finally */ }
```

**验收**
- [ ] 成功提交 → 数据库 `cube_record` 有 1 条、`cube_scramble` 有 N 条
- [ ] 故意让第 2 条打乱非法（超长/空）→ 请求失败，**两张表都没有数据**
- [ ] 失败后表单内容还在，提示是后端的 msg
- [ ] 提交中按钮禁用，不能重复提交

**前端联动**：对应 D16 事务；**前端不要自己"补偿"**（不要成功一半再删），一切以接口结果为准。

**坑**
- 空数组 `scrambles: []` 是否允许 → 问后端契约
- 重复点击提交 → `submitting` + `:disabled`
- 不要逐条 POST（等于放弃事务）
- 失败后不要 `window.alert`，用页面内提示（和现有风格一致）

**3 行笔记**：① 一次请求对应后端什么 ② 失败时为什么不能保留半条数据 ③ 动态表单怎么校验

## F9 · 登录页 + 注册页 · 对应后端 D17

> 状态：⬜ 未开始（等后端 `/user/register`、`/user/login`）

**目标**：能注册、能登录；密码只存在后端（前端不存明文）。

**契约（后端 D17）**：
```
POST /user/register  body:{username,password,nickname} → Result<Void>
POST /user/login     body:{username,password}          → Result<{token}>   （D17 先返回假 token，D18 换真 JWT）
```

**学**：`v-model` 表单；密码框；前端校验与后端校验的分工；成功后 `router.push`。

**做**
1. 新建 `/login`、`/register` 两个页面（复用一套表单样式）
2. `api/user.js`（或 records.js）加 `login()` / `register()`
3. 登录成功：**D17 阶段先存占位 token**；D18 拿到真 token 后换成真
4. 导航栏加「登录 / 注册」入口
5. 错误提示：用户名已存在、密码错误，都显示后端 `msg`

**验收**
- [ ] 注册成功 → 数据库 `user.password` 是 `$2a$...` 密文
- [ ] 重复用户名 → 显示错误，不跳转
- [ ] 登录成功 → 拿到 token（先存 localStorage）
- [ ] 密码错误 → 提示，停留当前页

**坑**
- 不要把密码 `console.log`
- 登录/注册接口**不带 token**（后端拦截器已排除）
- 前端校验只是体验，后端必须校验（已做）
- 成功后清理表单密码

**3 行笔记**：① 密码为什么不能在前端存 ② 登录成功的下一步要做什么 ③ 前端校验和后端校验各自作用

## F10 · Token 认证（前端核心）· 对应后端 D18

> 状态：⬜ 未开始（等后端 JWT 落地）

**目标**：全站带 token 请求；401 统一跳登录；刷新页面保持登录；退出登录清干净。

**契约（后端 D18，重大变更）**：
- 除登录/注册外，所有 `/record/**` 需要请求头 `Authorization: Bearer <token>`
- 无/错 token → **401**；成绩数据只返回当前用户
- 响应仍为 `Result{code,msg,data}`

**学**：`localStorage` 持久化；统一请求封装；路由守卫 `beforeEach`；401 与业务失败的区别。

**做**
1. 新建 `api/request.js`：封装 fetch → 自动加 `Authorization` → 统一解析 Result → 401 时清 token 并跳 `/login`
2. 现有 `api/records.js` 全部改为走 request（不再各自 fetch）
3. `router/index.js`：受限路由加 `meta.requiresAuth`；`beforeEach` 检查 token，无 → `/login?redirect=...`
4. App.vue 顶部：登录后显示用户名/「退出登录」（退出清 token + 跳登录）
5. 登录页支持 `redirect` 参数（登录后回到原页面）

**验收**
- [ ] 未登录访问 `/history` → 跳 `/login`
- [ ] 登录后回原页面；刷新仍登录（token 在 localStorage）
- [ ] 手动删 token 后刷新 → 被踢回登录
- [ ] 后端重启/错误 token → 401 → 清 token 跳登录，不白屏
- [ ] 业务失败（如时间非法）**不会**跳登录（只有 401 才跳）

**坑**
- 401 和业务错误都可能是 HTTP 200（看接口设计）→ 以状态码 401 或约定业务码判断，选一种并写进契约
- 路由守卫里避免死循环（`/login` 本身放行）
- fetch 封装里别把 FormData 请求头写死成 JSON

**3 行笔记**：① token 存在哪、什么时候带 ② 401 和 code:1 的区别 ③ 路由守卫的作用

## F12 · 分页条件扩展 · 对应后端 D20

> 状态：⬜ 未开始（等后端 `/record/page` 加条件参数）

**契约（后端 D20）**：`GET /record/page?page=&size=&minMs=&maxMs=&beginDate=&endDate=` → `{total, records}`

**目标**：把现有"搜索筛选"升级成"时间区间 + 日期区间"，翻页时保留条件。

**做**
1. `fetchRecordsPage(page, size, filters)` 支持附加参数（空值不传）
2. 历史页筛选区：秒数区间 + 日期区间；"筛选/清除"
3. 翻页时带着 filters 请求；改条件时 `page=1`
4. 空结果状态（"没有符合条件的成绩"）

**验收**
- [ ] 条件组合（只要最小/只要最大/两端/日期）都正确
- [ ] 翻页后条件还在；清除后回全量
- [ ] `total` 与筛选结果一致；越界页空列表不报错

**坑**：空字符串不要拼进 URL；日期用 `YYYY-MM-DD`；改条件必须重置页码
