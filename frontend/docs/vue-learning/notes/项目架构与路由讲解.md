## 1. 全景：前后端两个进程

```
浏览器
├── index.html（只有一个 <div id="app">）
└── src/main.js  →  createApp(App).use(router).mount('#app')
        │
        ▼
   App.vue（外壳）
   ├── 导航：RouterLink "/"（计时）、"/history"（历史）
   ├── <RouterView />   ← 路由出口：当前 URL 决定显示哪个页面
   └── 底部全局错误提示（来自 useRecords.error）
        │
        ├── "/"        → views/TimerView.vue
        └── "/history" → views/HistoryView.vue

页面里的数据请求统一走：api/records.js（唯一网络层）
        │  fetch('/api/record/...')
        ▼
  Vite 开发服务器代理：/api/* → http://localhost:8081/*（去掉 /api）
        ▼
  Spring Boot 后端（8081）
  Controller（路由/参数） → Service（校验/业务） → Mapper(XML, SQL) → MySQL
  返回统一结构：Result{code,msg,data}；分页时 data = PageResult{total,records}
```

### 前后端分工（本项目的定位）
- **后端是主线**：业务规则、校验、统计都在后端；接口契约由后端定义（权威文档：`backend/docs/springboot-learning/学习计划与进度.md`）
- **前端是辅助**：只负责展示和交互；接口形状变了，前端跟着改（见计划文档 §4.2 契约跟进表）

## 2. 前端目录分层（每个目录的职责）

| 目录/文件 | 职责 | 例子 |
|---|---|---|
| `index.html` | 唯一 HTML 入口，挂载点 `#app` | — |
| `src/main.js` | 创建应用、装路由、挂载 | `createApp(App).use(router).mount('#app')` |
| `src/App.vue` | 应用外壳：导航 + 路由出口 + 全局错误 | RouterLink / RouterView |
| `src/router/index.js` | 路由表：URL → 页面组件 | `/` → TimerView |
| `src/views/` | **页面级**组件（路由目标，负责"编排"） | TimerView、HistoryView |
| `src/components/` | **可复用**展示组件（不清楚业务上下文） | TimerDisplay、RecordList、StatCard、ScoreInput |
| `src/composables/` | 可复用的**状态/逻辑**（跨组件共享） | useRecords（records/loading/error） |
| `src/api/` | **唯一网络层**：所有 fetch 集中在这里 | records.js |
| `src/utils/` | 纯函数工具 | formatMs / formatDate / averageMs |
| `src/assets/` | 全局样式 | main.css |
| `vite.config.js` | 构建配置：`@` 别名、`/api` 代理 | — |

**为什么这样分**：页面（views）负责把多个组件拼起来；组件（components）保持通用、可复用；网络请求只写在一个地方（api），后端契约变了只改那一处；跨页面共享的数据用 composable。

## 3. 路由怎么工作（vue-router）

### 3.1 路由表
```js
const router = createRouter({
  history: createWebHistory(),          // HTML5 history 模式：URL 里没有 #
  routes: [
    { path: '/',        name: 'timer',   component: TimerView },
    { path: '/history', name: 'history', component: HistoryView },
  ],
})
```

### 3.2 三个核心概念
| 概念 | 作用 | 项目位置 |
|---|---|---|
| `RouterLink` | 生成 `<a>` 链接；点击时**不刷新页面**，只切 URL | App.vue 的两个 tab |
| `RouterView` | 路由出口：根据当前 URL 渲染对应页面组件 | App.vue 的 `<main>` 里 |
| `routes` | URL ↔ 组件的映射表 | router/index.js |

- `RouterLink` 激活时会自动加 `.router-link-active` class（main.css 用它做高亮）
- 刷新 `/history` 时浏览器会请求服务器 `/history`，开发期 Vite 会自动回退到 index.html；**部署到 Nginx 需要 `try_files $uri /index.html;`**，否则刷新 404

### 3.3 页面切换时发生什么
```
点击"历史" → URL 变 /history → RouterView 卸载 TimerView（触发 onBeforeUnmount）
→ 挂载 HistoryView（触发 onMounted → loadPage 拉第 1 页）
```
所以：**页面组件里的状态会随切页面丢失**（比如 HistoryView 的当前页码会回到 1）——这是正常的。

## 4. 组件树：父子关系

```
App.vue（根组件）
├── <nav class="tabs"> 两个 RouterLink
├── <RouterView>
│   ├── TimerView（路由 "/"）           ← 页面组件
│   │   ├── TimerDisplay               子组件（计时 + emit finish）
│   │   ├── ScoreInput                 子组件（输入 + emit add）
│   │   ├── StatCard ×2                子组件（显示 AVG5 / AVG12）
│   │   └── RecordList ×1              子组件（显示最近 5 次，无删除）
│   └── HistoryView（路由 "/history"）  ← 页面组件
│       └── RecordList                 子组件（显示当页数据 + 删除按钮）
└── <p class="msg"> 全局错误提示
```

- TimerView / HistoryView 之间是"兄弟页面"关系，**不直接通信**；它们共享的后端数据通过各自的加载逻辑获取
- `RecordList` 是**同一个组件**被两个页面复用：靠 props 开关显示差异（`showDate` / `showDelete`）
- TimerDisplay / ScoreInput / StatCard / RecordList 都**没有子组件**

## 5. 父子通信的四种方式（本项目实际用到 3 种）

| 方向 | 机制 | 代码 | 项目例子 |
|---|---|---|---|
| 父 → 子 | **props**（`defineProps`） | `<RecordList :records="recentRecords" />` | TimerView → RecordList；HistoryView → RecordList |
| 子 → 父 | **emit**（`defineEmits` + 父模板 `@事件`） | 子：`emit('finish', ms)`；父：`@finish="handleFinish"` | TimerDisplay → TimerView；RecordList `delete` → HistoryView |
| 共享状态 | **composable 单例**（模块级 ref） | `const { records, error } = useRecords()` | App（显示 error）和 TimerView（load/add）共用 |
| 兄弟通信 | 通过父组件中转 / 共享 composable | — | 本项目暂无直接兄弟通信 |

### 5.1 最容易踩的坑
1. **props 单向**：子组件不能直接改父组件传来的 props（要改让父组件改）
2. **emit 两边都要写**：子组件 `defineEmits(['delete'])` 只是"能发"；父组件模板必须 `@delete="handleDelete"` 才"能收"（F5 就漏过这里，按钮不显示）
3. **composable 不是父子传值**：`useRecords()` 是模块级单例，谁调用谁拿到同一份数据，不存在"父传子"关系

## 6. 一次完整的数据流（两条真实链路）

### 6.1 计时结束 → 保存成绩
```
用户点"停止"
→ TimerDisplay.stop()          计算总毫秒，emit('finish', Math.round(total))
→ TimerView.handleFinish(ms)
→ useRecords.add(ms)           error 清空
→ api.createRecord(ms)         POST /api/record?timeMs=...
→ Vite 代理 → 后端 Controller.add → Service.add（校验 0<ms<=600000）
→ Mapper.insert → MySQL
→ 返回 Result{code:0}
→ useRecords.load(true)        再 GET /record/list 拉最新列表
→ records.value 更新 → computed（recentRecords/avg5/avg12）自动重算 → 页面刷新
```

### 6.2 历史页删除一条
```
用户点"删除" → RecordList emit('delete', item.id)
→ HistoryView.handleDelete(id) → window.confirm 确认
→ api.deleteRecord(id)         DELETE /api/record/{id}
→ 后端 Controller.delete → Service.delete（检查影响行数，0 → "记录不存在"）
→ 返回 Result{code:0}
→ HistoryView.loadPage()       重新 GET /record/page?page=&size=
→ rows / total 更新 → 分页和列表刷新
```
