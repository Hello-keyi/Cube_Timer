## 一、你的 4 个回答逐条点评

### Q1「为什么 ref 在 script 里要 .value，模板里不用？」
你的答案：Vue 会帮我编译，自动解包机制 → **半对（理解了表层）**

- 对的：模板里确实不用 `.value`，是"自动解包"。
- 补全：`ref(0)` 返回的是一个**包装对象** `{ value: 0 }`，它的 `value` 是 getter/setter（读时收集依赖、写时触发更新）。
  - script 里：`count.value` 才会走 getter/setter；直接写 `count = 1` 只是换了个普通变量，响应式丢了。
  - 模板里：Vue 在**编译模板**时（构建期）把模板编译成 render 函数，对顶层 ref 自动补上 `.value` 访问——所以是"编译器帮你写了 .value"，不是运行时魔法。
- 一句话：**模板自动解包是编译器帮忙；script 里没人帮你，必须自己 .value。**

### Q2「computed 是什么？缓存什么意思？」
你找的代码：`HistoryView.vue` 第 7 行
```js
const count = computed(() => records.value.length)
```
**你找对了，这行就是标准的 computed 例子**（我上一条举例用的是 `TimerView.vue` 的 `recentRecords`，两处都对）。

- 你的理解"把括号里的操作赋给 count"→ 更准确：`computed` 接收一个**计算函数**，返回一个"只读的响应式计算结果"。
- 模板里写 `{{ count }}` 直接用；`records` 变了它会自动重算。
- **缓存**：`records` 没变时，不管读 `count` 多少次，计算函数**只执行过一次**（第一次），之后直接拿缓存值；只有依赖（`records.value`）变化才重新执行。
- 对比：普通函数 `function getCount() { return records.value.length }`，每读一次就执行一次，没有缓存。

### Q3「什么时候用 watch 而不是 computed？」
你的答案：watch 是 watch，computed 是 computed；改 watch 里的请求不执行 → **理解偏了（没答到点上）**

正确的区分（很重要，F4/F5 还会用）：

| | `computed` | `watch` |
|---|---|---|
| 用途 | **算出一个值**，给模板/别的计算用 | 值变了之后**做一件事**（副作用） |
| 是否产生新值 | 是（有返回值） | 否（不返回值，只执行回调） |
| 是否有副作用 | 不应该有（纯计算） | 就是干副作用的：发请求、存 localStorage、打印日志、弹提示、开定时器 |
| 缓存 | 有 | 无（每次变化都触发） |
| 项目例子 | `recentRecords`、`avg5`、`count`、`total` | "新增成绩后自动存到 localStorage"、"当 count 变化时弹提示/上报埋点"、"监听筛选条件变化后请求后端" |

- 口诀：**要一个"值" → computed；要一个"动作" → watch**。
- watch 回调参数：`watch(源, (newVal, oldVal) => { ... })`；深度监听对象要 `{ deep: true }`。
- 你代码里 `watch(count, (n, o) => msg.value = ...)` 思路是对的 ✓ 但**必须先 import watch**。

### Q4「reactive 对象解构后还有响应性吗？」
你的答案：不改变，属性和普通变量不一样 → **结论对（但对原因的表述含糊）**

- 原因：解构是**取值拷贝**。
```js
const state = reactive({ count: 0 })
const { count } = state      // count 只是数字 0 的拷贝
state.count++                // state.count 变了，但局部 count 还是 0，页面不会更新
```
- 正确做法：① 不解构，用 `state.count`；② 或 `const { count } = toRefs(state)`（拿到 ref，模板自动解包）。
- **反例提醒（别混淆）**：从 composable 解构 ref **不会丢响应**：
```js
const { records } = useRecords()   // records 本身是 ref 包装对象，解构的是"引用"，仍然响应
```
  区别在于：解构 `reactive` 是拆出"值"，解构 composable 返回的是"ref 包装对象"。

**小计**：Q1 半对、Q2 对、Q3 偏、Q4 半对 → 约 **1.5~2 / 4**。概念方向没错，需要补细节。
