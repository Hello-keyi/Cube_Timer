## 一、知识地图（一张图记住全貌）

```
数据（后端 MySQL）
   │  GET/POST/PUT/DELETE，统一返回 Result{code,msg,data}
   ▼
api/records.js          ← 唯一网络层：fetch → json → 判 code → 返回 data / 抛 Error
   │
   ▼
composables/useRecords.js（可选共享层：records / loading / error 模块单例）
   │
   ▼
views/（页面）：TimerView、HistoryView   ← 负责编排 + 状态管理 + 调 API
   │  props 往下 / emit 往上
   ▼
components/（组件）：TimerDisplay、RecordList、StatCard、ScoreInput
   │  纯展示：props 进、emit 出，不发请求
   ▼
router/index.js：URL ↔ 页面（/ 和 /history）
App.vue：外壳（导航 RouterLink + 出口 RouterView + 全局错误）
```

**一句话**：页面负责"要数据、管状态"，组件负责"显示和通知"，api 负责"跟后端说话"。

## 二、每课要点（只记这些）

### F1 模板语法
| 语法 | 作用 | 注意 |
|---|---|---|
| `{{ 表达式 }}` | 插值 | 里面是 JS 表达式，不是语句 |
| `v-if` / `v-else-if` / `v-else` | 条件渲染（真删/建 DOM） | 有切换成本 |
| `v-show` | 切 `display`，元素始终渲染 | 频繁切换用它 |
| `v-for="(item, index) in list"` + `:key` | 列表 | key 用唯一 id，别用随机值；不写不报错但会按索引复用 DOM |
| `:属性="变量"` | v-bind（单向绑定） | 去掉冒号就变普通字符串 |
| `@事件="处理函数"` | v-on | `@click="count++"` 可行（模板里 ref 自动解包） |
| `:class="{ 'x': 条件 }"` | 动态 class | 对象/数组两种写法 |

**踩过的坑**：`<script>` 不等于 `<script setup>`（模板拿不到变量）；`defineProps` 和 `defineExpose` 别混；模板里用的函数/变量必须 import。

### F2 响应式
| 概念 | 要点 |
|---|---|
| `ref(x)` | 包装对象，script 里 `.value`，模板自动解包（编译器帮你）。模板事件里 `count++` 也行（proxyRefs 代理 setupState） |
| `reactive(obj)` | 只能对象；解构会丢响应性（用 `toRefs` 或 `state.x`） |
| `computed(fn)` | 派生值：有缓存、依赖变了自动重算、无副作用。用 `totalPages/canPrev/canNext/avg5` 这类 |
| `watch(source, cb)` | 副作用：请求、存储、日志、定时器。`(newVal, oldVal)`；`watch(page, loadPage)` |
| 口诀 | **要一个"值" → computed；要一个"动作" → watch** |

**踩过的坑**：`throw new (json.msg)` 不是合法写法（要 `new Error(...)`）。

### F3 组件通信
| 方向 | 写法 | 项目例子 |
|---|---|---|
| 父 → 子 | `defineProps({...})` + 父模板 `:prop="变量"` | TimerView → RecordList 传 `records` |
| 子 → 父 | `defineEmits(['x'])` + `emit('x', 数据)`；父模板 `@x="fn"` | TimerDisplay `emit('finish', ms)` |
| 共享 | composable 模块级 ref | `useRecords()` 的 `records/loading/error` |
| 生命周期 | `onMounted`（挂载后）、`onBeforeUnmount`（卸载前清理） | TimerView 拉数据；TimerDisplay 停 rAF |

**踩过的坑**：emit 两边都要写（子 `defineEmits` + 父 `@事件`）；props 单向，子组件不能直接改。

### F4 路由 + 接口层 + 异步
- `createRouter({ history: createWebHistory(), routes })`；`RouterLink` 导航、`RouterView` 出口；刷新 `/history` 靠服务器回退 index.html（Nginx `try_files $uri /index.html;`）
- 404 兜底：`{ path: '/:pathMatch(.*)*', component: NotFoundView }`
- **fetch 对 4xx/5xx 不 reject**；本项目必须判 `json.code !== 0`（HTTP 200 也可能是业务失败）
- 异步三态：`loading` / `errorMsg` / 正常数据，用 `try/catch/finally` 维护

### F5 分页 + 删除
- 分页状态：`page / SIZE / total / rows` + `loading / errorMsg`
- 派生：`totalPages = ceil(total/SIZE)`、`canPrev = page>1`、`canNext = page<totalPages`
- `watch(page, loadPage)`：翻页自动请求；删除后 `await loadPage()` 刷新（以服务端为准，total 会变）
- 删除流程：子组件 `emit('delete', id)` → 父组件 confirm → `deleteRecord(id)` → 重新加载
- 边界：删空当前页要回上一页（loadPage 里的兜底）

### F6 出参/统计（D8 + D12）
- 后端出参 `CubeRecordVO`：`id / timeMs / timeText / createdText`（**没有 createdAt**）
- 后端入参 DTO：`POST /record` 用 `@RequestBody CubeRecordAddDTO`（JSON body `{timeMs}`），不再是 query 参数
- 统计：`GET /record/stats` → `total / bestText / worstText / avg5Text / avg12Text / todayBestText`；前端**不再自己算 AVG**
- 原则：**能后端算的业务就后端算，前端只做展示**

## 四、答案（先自己做，再对）

**A 组**
1. `v-if` 真删/建 DOM（切换成本高）；`v-show` 元素始终在，只切 `display`（切换便宜）。频繁切换用 v-show，条件少变用 v-if。
2. 给列表项稳定身份，Vue 按 key 复用/移动 DOM。不写不报错，但会按索引复用，重排/删除时可能状态错乱、性能差。
3. 普通 `<script>` 的变量是模块作用域，不暴露给组件实例；`<script setup>` 是编译期语法糖，编译器把顶层绑定注入模板上下文（return 到 render）。
4. `ref` 返回的是包装对象 `{value}`，`.value` 是 getter/setter（收集依赖/触发更新）；模板在编译时自动补 `.value`（编译器帮忙），所以不用写。
5. computed = 派生值（有缓存、无副作用，如 `recentRecords`、`avg5`、`totalPages`）；watch = 副作用（值变了做事，如 `watch(page, loadPage)` 发请求、存 localStorage）。

**B 组**
6. 单向：父传子，子只读。子直接改会警告，要改就让父组件改（或 emit 通知父）。
7. 父模板必须写 `@delete="处理函数"` 接收；只写 `defineEmits` 只是"能发"，没人接等于没用。
8. `onMounted` 挂载后（拉数据）；`onBeforeUnmount` 卸载前（清理 rAF/定时器，防内存泄漏/重复执行）。
9. 不会。fetch 只有网络层失败才 reject；HTTP 错误是正常响应。本项目额外判断业务码：`json.code !== 0` 才算失败（HTTP 200 也可能 code=1）。
10. 开发期 Vite 自动回退 index.html；部署 Nginx 要 `try_files $uri $uri/ /index.html;`，否则刷新 404。

**C 组**
11. `page / SIZE / total / rows`，加 `loading / errorMsg`；`totalPages = Math.max(1, Math.ceil(total / SIZE))`。
12. 以服务端为准：total 会变、翻页边界会变、别的端可能也改了数据；本地 filter 要自己维护 total，容易不同步。
13. `id / timeMs / timeText / createdText`；没有 `createdAt` 了（VO 只给格式化后的 `createdText`），所以 `formatDate(item.createdAt)` 会拿到 undefined 显示空。
14. 从后端 `GET /record/stats` 的 `avg5Text` 来；业务计算归后端（换个前端也还得有），前端只展示。
15. TimerDisplay 计时 → `emit('finish', ms)` → TimerView `handleFinish` → `useRecords.add` → `api.createRecord`（POST JSON）→ Vite 代理 `/api` → Controller → Service（校验/组装 VO）→ Mapper XML → MySQL → 返回 `Result` → 前端更新 `records` / 重新 `loadStats` → computed 重算 → 模板刷新。

## 五、如果只能记 5 句话

1. 模板里用到的变量/函数，必须在 `<script setup>` 里 import 或定义。
2. `ref` script 里 `.value`，模板自动解包；要值用 computed，要动作用 watch。
3. props 往下走，emit 往上走，两边都要写。
4. 页面（views）管状态和请求，组件（components）只管显示和通知，api 层统一说话。
5. 接口返回先判 `json.code`；业务计算尽量交给后端。
