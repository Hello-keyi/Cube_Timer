## 0. 这一课学什么

- **动态路由**：URL 里带参数 `/record/:id`，同一个页面显示不同数据
- **useRoute / useRouter**：读路由参数、代码里跳转页面
- **新接口调用**：GET 详情（返回 `scrambles` 数组）+ POST 添加打乱
- **表单提交**：输入 → 校验 → 提交 → 刷新数据（状态处理）

## 3. 任务清单（按顺序做）

### F7-5（先做 api，最像 F4/F5 的套路）
`src/api/records.js` 里实现：
```js
export async function fetchRecordDetail(id) { ... }   // GET /record/{id}
export async function addScramble(id, scramble) { ... } // POST /record/{id}/scramble?scramble=...
```
提示：
- 和 `fetchRecords` 一模一样：`fetch` → `res.json()` → `if (json.code !== 0) throw new Error(json.msg || '...')` → `return json.data`
- POST 的 `scramble` 要 `encodeURIComponent(scramble)`（里面有空格/引号）
- 成功后 `addScramble` 没有 data，可以只 `return`

### F7-1：`DetailView.loadDetail()`
- 调 `fetchRecordDetail(recordId.value)`，结果赋给 `detail`
- 已有的 try/catch/finally 不用动

### F7-2：`DetailView.submitScramble()`
1. `newScramble.value.trim()` 为空 → 直接 return（或写 errorMsg）
2. `submitting.value = true`
3. `await addScramble(recordId.value, newScramble.value)`
4. 成功：清空输入 + `await loadDetail()`（或 `detail.value.scrambles.push(newScramble.value)`）
5. 失败：`errorMsg.value = '添加失败：' + e.message`
6. 最后 `finally { submitting.value = false }`

### F7-3：`goBack()`
- `router.push('/history')` 或 `router.back()`

### F7-4：打乱列表空状态
- 你已经有 `v-for`；补一个 `v-else` 的"还没有打乱记录"
