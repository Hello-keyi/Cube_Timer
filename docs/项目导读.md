## 1. 项目全景

### 1.1 一句话

记录魔方成绩：计时/手动录入 → 存 MySQL（按用户隔离）→ 分页/筛选/详情/打乱 → 统计（AVG5/12）→ 导出 Excel / 图片上传 / WebSocket 实时刷新；每天凌晨定时聚合统计。

### 1.2 技术栈

| 层 | 技术 |
|---|---|
| 后端 | JDK 21、Spring Boot 4.0.8、MyBatis（注解 + XML）、MySQL 8、Redis、PageHelper、JWT（jjwt）、AOP（AspectJ）、WebSocket、Apache POI、springdoc（dev） |
| 前端 | Vue 3.5、vue-router 4、Vite 5、ECharts |
| 部署 | Nginx（静态 + 反向代理 + WebSocket 升级）、可执行 jar、一键启停脚本 |

### 1.3 运行拓扑

```
浏览器 http://127.0.0.1:80
 ├─ /           → Nginx 静态文件 frontend/dist（Vue SPA，history 路由回退 index.html）
 ├─ /api/       → 反代 jar:8081（去掉 /api 前缀）
 ├─ /uploads/   → 反代 jar（图片静态映射）
 └─ /ws/        → 反代 jar（WebSocket Upgrade）
                   ↓
          jar :8081 → MySQL :3306 + Redis :6379
```

## 4. 后端导读

### 4.1 多模块与依赖方向

```
common（无业务依赖）  ←  pojo（依赖 common）  ←  server（依赖 common + pojo）
```
- `common`：`Result`、`PageResult`、`BusinessException`、`BaseContext`、`JwtUtil`、`StatsUtils`、`AutoFill` 注解、`OperationType` 枚举、`JwtProperties`
- `pojo`：`entity`（数据库映射）、`dto`（入参）、`vo`（出参）
- `server`：全部 Web 层 + Service + Mapper + 配置

**阅读顺序建议**：先 `common` 里 2~3 个类，再 `pojo` 的 entity/vo，最后 `server`。

### 4.2 分层职责（一句话版）

| 层 | 位置 | 职责 |
|---|---|---|
| Controller | `server/.../controller/` | 路由、参数绑定、调 Service、包 `Result` |
| Service（接口 + 实现） | `server/.../service/` | 业务规则、事务、校验、组装 VO |
| Mapper | `server/.../mapper/` + `resources/mapper/*.xml` | 只负责 SQL |
| Entity / DTO / VO | `pojo/.../` | 数据库映射 / 入参 / 出参（VO 不含密码） |
| 横切 | `config/` `interceptor/` `aspect/` `handler/` `task/` `websocket/` | 拦截器、AOP、异常、定时任务、WS |

### 4.3 一条完整调用链（以「批量录入成绩」为例）

```
POST /record/full  {timeMs, scrambles[]}
 → CubeRecordController#addFull(@Valid @RequestBody CubeRecordFullDTO)
 → CubeRecordServiceImpl#addFull           ← @Transactional(rollbackFor=Exception.class)
      ├─ currentUserId()                   ← BaseContext（拦截器里写入的 userId）
      ├─ CubeRecordMapper#insert(record)   → mapper XML → insert into cube_record(...)
      ├─ CubeScrambleMapper#insert(...)    → 每条打乱一条记录
      ├─ evictStatsCache()                 → Redis 删 cube:stats:{userId}
      └─ 任一异常 → 两张表一起回滚
 → 返回 Result<Void>
（单条新增 /record 还会 WebSocketServer.broadcast 一条 NEW_RECORD）
```

读这条链时，**同时看** 4 个文件：Controller → ServiceImpl → Mapper 接口 → Mapper XML。

### 4.5 推荐阅读顺序（5 条线，由浅入深）

1. **登录线**（理解鉴权闭环）
   `UserController` → `UserServiceImpl` → `JwtUtil` → `JwtTokenInterceptor` → `WebMvcConfig` → `BaseContext`
2. **成绩 CRUD 线**（理解分层）
   `CubeRecordController` → `CubeRecordServiceImpl` → `CubeRecordMapper`（接口 + XML）→ `CubeRecordVO`
3. **分页/筛选线**（理解 PageHelper + 动态 SQL）
   `page` 接口 → `PageHelper.startPage` → `listForPage` XML `<where><if>` → `PageResult`
4. **统计/缓存线**（理解业务计算 + Redis）
   `stats` 接口 → `StatsUtils` → Redis 读写/失效 → `RecordStatsVO`
5. **横切与外围线**
   事务（`addFull`）、AOP（`AutoFillAspect`）、定时任务（`DailyStatTask`）、WebSocket、上传、导出

## 5. 数据库导读（4 张表）

`cube_timer.sql` 可完整重建库。字段含义：

| 表 | 关键字段 | 说明 |
|---|---|---|
| `user` | id, username(唯一), password(BCrypt), nickname, status, create_time | 登录用户 |
| `cube_record` | id, **user_id**, time_ms, create_time, update_time, **create_user**, **update_user** | 一条成绩；后 4 个字段由 AOP 自动填充；`user_id` 有索引 |
| `cube_scramble` | id, **record_id**, scramble, seq | 打乱公式 1:N；`record_id` 外键级联删除 |
| `daily_stat` | id, stat_date, user_id, total_count, best_ms, avg_ms, create_time | 定时任务每日聚合结果 |

**关系**：`user 1—N cube_record 1—N cube_scramble`；`user 1—N daily_stat`。

**建议动手 SQL**：
```sql
select * from cube_record where user_id = 4 order by id desc limit 3;
select count(*), min(time_ms), max(time_ms) from cube_record where user_id = 4;
select r.id, r.time_ms, s.seq, s.scramble
from cube_record r left join cube_scramble s on s.record_id = r.id
where r.user_id = 4 order by r.id desc, s.seq;
```

### 6.2 启动链路

```
index.html → src/main.js（createApp + router + main.css）→ App.vue
   → <RouterView> 按 URL 加载对应 view（懒加载 chunk）
```

### 6.3 请求层链路（前端最重要的读法）


### 6.5 前端已做的优化（读的时候留意）

- 路由**全部懒加载**（首屏 main bundle ~102KB，ECharts 单独 chunk 只在统计页加载）
- ECharts **按需引入**（`echarts/core` + `BarChart` + `Grid/Tooltip` + `CanvasRenderer`）
- 401 统一处理（保留 `redirect`，避免登录页死循环）
- 退出登录清空成绩缓存（`useAuth.logout → useRecords.reset`）

## 7. 部署导读

| 文件/位置 | 说明 |
|---|---|
| `/etc/nginx/sites-available/cube-timer` | 站点配置：root 指向 `frontend/dist`；`try_files ... /index.html` 支持 SPA；`/api/`、`/uploads/`、`/ws/` 三段反代 |
| `backend/server/target/server-0.0.1-SNAPSHOT.jar` | 可执行 jar（多模块后产物在 server 模块） |
| `scripts/start.sh` / `stop.sh` | 启停 MySQL / Redis / Nginx / jar（root 执行） |
| `一键启动.bat` / `一键停止.bat` | Windows 双击版（调 WSL 脚本） |
| `frontend/dist/` | `npm run build` 产物，Nginx 直接托管 |

**Nginx 三个关键点**（也是常见坑）：
1. `location /api/ { proxy_pass http://127.0.0.1:8081/; }` —— 末尾 `/` 会去掉 `/api` 前缀；
2. `location /uploads/`、`location /ws/` 的 `proxy_pass` **不能**带末尾 `/`，否则前缀会被吃掉；
3. `/ws/` 需要 `proxy_http_version 1.1` + `Upgrade`/`Connection` 头。

更多见 `frontend/docs/vue-learning/notes/部署方案.md`。

## 8. 常见坑（都是本项目真实踩过的）

| 坑 | 现象 | 原因/解决 |
|---|---|---|
| MySQL 没起 | 所有接口 `系统繁忙` | WSL 重启后 MySQL 不自启：`sudo service mysql start` |
| 后端被 Ctrl+Z | 端口在监听但请求超时（无响应） | 进程状态 `T`：`kill -CONT <pid>` 或重启用 Ctrl+C 停止 |
| `/api/api/...` 404 | 前端接口全 404 | api 层重复拼了 `/api`（`request()` 内部已加） |
| 401 白屏/死循环 | 页面直接跳登录 | `request.js` 里 401 处理要带 `redirect`，且已在 `/login` 时不再跳 |
| 刷新子路由 404 | `/history` 刷新 404 | Nginx 需要 `try_files $uri $uri/ /index.html;` |
| 上传图片 404/500 | 图片打不开 | Nginx 缺 `/uploads` 反代，或 `proxy_pass` 尾斜杠吃前缀 |
| WebSocket 连不上 | 控制台 WS error | Vite/Nginx 未配 `/ws` 代理或缺少 Upgrade 头 |
| PageHelper 分页错位 | 条数不对/条件丢失 | `startPage()` 后必须**紧跟**那一条查询 |
| ThreadLocal 串号 | 用户数据错乱 | 拦截器 `afterCompletion` 必须 `BaseContext.removeCurrentId()` |
| 事务不生效 | 一半成功一半失败 | 自调用/非 public/异常被 catch 吞掉；用 `rollbackFor` |
| 前端页面 500 | `Failed to resolve import` | VS Code 自动导入插入了 `vue-router/dist/router-*.mjs` 之类垃圾 import，检查文件头 |
| 缓存串用户 | A 看到 B 的统计 | Redis key 必须带 userId（`cube:stats:{userId}`） |

## 10. 和「寒页外卖」的对照（迁移学习）

| 寒页外卖 | 本项目对应 | 状态 |
|---|---|---|
| 员工/用户双端 JWT + 拦截器 | 单端 JWT + 拦截器 + BaseContext | ✅ 已实现 |
