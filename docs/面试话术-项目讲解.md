# 面试话术 · Cube_Timer 项目讲解

> 用途：面试时怎么讲这个项目。按「30 秒 → 2 分钟 → 深挖」三层准备。
> 仓库：https://github.com/Hello-keyi/Cube_Timer

---

## 一、30 秒版本（自我介绍时提一句）

> 我做过一个魔方成绩管理系统，是个前后端分离的全栈项目。
> 后端用 Spring Boot 4 多模块 + MyBatis + MySQL + Redis，
> 实现了用户注册登录、JWT 鉴权与数据隔离、成绩 CRUD 与分页统计、
> 成绩导出 Excel、图片上传、定时任务和 WebSocket 实时推送。
> 前端用 Vue 3。整个项目从建库到部署都是我自己完成的。

**要点**：一句话说完技术栈 + 功能范围 + "独立完成"。

## 二、2 分钟版本（项目介绍题）

> **背景**：我自己玩魔方，想记录和统计成绩，市面上工具不够贴合需求，就自己做了。
> 同时也是想通过一个完整项目把后端的常用机制走一遍。

> **架构**：后端是 Maven 多模块，拆成 `common`（通用能力）、`pojo`（数据对象）、
> `server`（业务服务）三个模块。`server` 依赖另外两个，反向不依赖，
> 这样依赖边界由编译器强制保证。

> **分层**：Controller → Service（接口 + 实现）→ Mapper → MySQL。
> 接口出入参用 DTO 和 VO，Entity 只在 Service 和 Mapper 之间传递。

> **核心功能**：
> - 用户：BCrypt 存密码，登录签发 JWT；
> - 鉴权：拦截器校验 token，解析出 userId 放进 ThreadLocal，
>   所有业务 SQL 都带 `user_id` 过滤，做到数据隔离；
> - 成绩：CRUD、分页（PageHelper）、按耗时区间筛选；
> - 统计：AVG5/AVG12 按 WCA「去头尾」规则算，走 Redis 缓存；
> - 还有：Excel 导出、图片上传、每日统计定时任务、WebSocket 实时推送。

> **工程化**：统一返回 `Result<T>`、全局异常分级处理、参数校验、
> AOP 自动填充审计字段、请求耗时日志、OpenAPI 文档、JUnit 测试、可执行 jar 打包。

**要点**：先讲"为什么做"，再讲"架构"，最后讲"功能 + 工程化"。**控制在一分半到两分钟。**

## 三、六个核心亮点（每题准备 1–2 分钟展开）

### 亮点 1：JWT 鉴权链路 + 数据隔离 ⭐ 最值得讲

**讲法：**

> 登录时用 BCrypt 校验密码，成功后签发 JWT，payload 里只放 userId，有效期 2 小时。
> 前端把 token 存 localStorage，之后每个请求带 `Authorization: Bearer <token>`。
>
> 后端用拦截器拦截 `/record/**`：
> 1. 从请求头取 token，`Bearer ` 前缀去掉；
> 2. 用 `JwtUtil.parseJWT` 验签 + 校验过期；
> 3. 解析出 userId，放进 `BaseContext`（ThreadLocal）；
> 4. 请求结束时在 `afterCompletion` 里调用 `remove` 清理。
>
> Service 层通过 `BaseContext.getCurrentId()` 拿到当前用户，
> 所有 Mapper 查询都带 `where user_id = ?`。

**为什么值得讲**：这一条覆盖了 JWT、拦截器、ThreadLocal、数据隔离四五个知识点。

**可能的追问**：见第五节。

### 亮点 2：事务边界

**讲法：**

> 有一个接口叫 `/record/full`，一次提交「成绩 + 多条打乱公式」，涉及两张表的写入。
> 我在 Service 方法上加了 `@Transactional(rollbackFor = Exception.class)`，
> 保证要么全成功、要么全回滚。
>
> `rollbackFor` 不能省：Spring 默认只回滚 `RuntimeException`，受检异常默认不回滚。
>
> 我做过验证：故意让第二条打乱超长导致数据库报错，
> 有注解时成绩也被回滚了；去掉注解后，成绩留在库里但打乱只进了一条 —— 数据不一致。

**加分点**：说"我做过对比验证"比只说"我用了事务"强很多。

### 亮点 3：AOP 自动填充审计字段

**讲法：**

> 表里有 `create_time / create_user / update_time / update_user` 四个审计字段。
> 如果在每个 Service 里手写赋值，重复且容易漏。
>
> 我自定义了 `@AutoFill(OperationType.INSERT/UPDATE)` 注解，
> 加在 Mapper 的 insert/update 方法上；
> 切面用 `@Before` + 切点 `execution(* ..mapper.*.*(..)) && @annotation(AutoFill)` 拦截，
> 通过反射给实体赋值：INSERT 填 4 个，UPDATE 只填前两个（创建信息不能被改）。
>
> 踩过一个坑：注解必须加 `@Retention(RUNTIME)`，默认是 CLASS，运行时就没了，切面读不到。

### 亮点 4：Redis 缓存策略

**讲法：**

> 统计接口要跑 5 条 SQL（count / min / max / 最近 5 次 / 最近 12 次 / 今日最佳），
> 但统计页是高频访问的，所以加了缓存。
>
> 设计是：
> - key 是 `cube:stats:{userId}`，**必须带用户维度**，否则 A 用户会读到 B 用户的统计；
> - TTL 60 秒；
> - 读：先查 Redis，命中直接返回；
> - 写：增删改成功后主动 `delete` 缓存（Cache Invalidation）；
> - **每一步都 try-catch**：缓存挂了要降级查库，不能让接口 500。
>
> 实测：第一次请求控制台有 6 条 SQL，第二次请求只有一条"命中缓存"日志，零 SQL。

### 亮点 5：Maven 多模块

**讲法：**

> 拆成三个模块：`common` 放 Result、PageResult、异常、JWT 工具、ThreadLocal 上下文；
> `pojo` 放 entity / dto / vo；`server` 放 controller / service / mapper / 配置 / 拦截器 / 切面。
>
> 依赖方向是单向的：server → common / pojo，反向不依赖。
> **好处是边界由编译器强制** —— 比如在 pojo 里调用 Service 会直接编译失败。
>
> `spring-boot-maven-plugin` 只放在 server 模块，否则 common/pojo 也会被 repackage 成 fat jar。
>
> 踩过的坑：同一个库被两个模块以不同版本引入，会有 `NoSuchMethodError`，
> 需要用 `mvn -pl <module> dependency:tree` 逐模块核对版本。

### 亮点 6：WebSocket 实时推送

**讲法：**

> 新增成绩时，通过 WebSocket 广播给所有在线客户端，前端页面自动刷新。
> 用的是 Jakarta WebSocket 规范（`@ServerEndpoint`），不是 Spring 的 STOMP。
>
> 关键点：
> 1. 必须注册 `ServerEndpointExporter` Bean，否则 `@ServerEndpoint` 完全不生效（连接 404）；
> 2. 在线连接用 `ConcurrentHashMap<String, Session>` 管理；
> 3. 广播方法要 `synchronized`，因为 `getBasicRemote().sendText()` 不是线程安全的；
> 4. 每个连接单独 try-catch，一个连接失败不能影响其他连接。

## 四、我做的技术决策（展示思考过程）

面试官很爱问"为什么这么设计"。准备这几个：

### Q：为什么用 JWT 而不是 Session？

> Session 是服务端存储，有状态，多实例部署时要解决 session 共享（要么粘性会话，要么 Redis 存 session）。
> JWT 是自包含的，服务端不存状态，天然适合水平扩展。
> 代价是**无法主动失效** —— 要强制下线得靠 tokenVersion 或黑名单，这个我了解但没做。
> 这个项目是单机部署，其实 Session 也能满足；选 JWT 主要是想练这个技术。

**加分**：承认"我的场景其实不一定需要 JWT"比硬吹更可信。

### Q：为什么 Entity 不直接当接口出入参？

> 三个原因：
> ① 安全：直接收 Entity，前端能伪造 `id`、`createdAt` 这类不该传的字段（批量赋值攻击）；
> ② 稳定：表加字段会自动暴露到接口，改库就影响 API；
> ③ 灵活：VO 可以加表里没有的字段，比如 `timeText`（"1.234" 秒），
>    这样格式化规则统一在后端，前端网页/小程序/App 都一致。

### Q：为什么统计用 Java 算 AVG5 而不用 SQL？

> 去头尾平均在 SQL 里要窗口函数 + 子查询，很绕；Java 里就是排序 + 去首尾 + 求平均。
> 我的原则是：**SQL 擅长筛选/聚合/连接，复杂业务规则放应用层。**

### Q：数据隔离为什么在 SQL 层做，不在 Java 层判断？

> SQL 层做的话，查不到就是查不到，天然安全。
> 如果先查出来再在 Java 里判断 `if (record.userId != currentUser)`，
> 一旦漏了某个分支就是越权。
>
> 而且越权访问我统一返回「记录不存在」而不是「无权限」——
> 返回「无权限」等于告诉攻击者"这条数据存在，只是不属于你"。

## 五、高频追问 + 回答（20 问）

### JWT / 鉴权

**Q1：JWT 的三段是什么？为什么改了 payload 会失效？**
> Header.Payload.Signature。签名是 `HMAC(base64(header) + "." + base64(payload), secret)`。
> 改了 payload，签名就对不上；而 secret 只在服务器，攻击者算不出新签名。
> **注意 payload 只是 base64 编码，不是加密**，所以只能放 userId 这种不敏感的信息。

**Q2：token 有效期多长？过期了怎么办？**
> 2 小时。过期后前端收到 401，跳登录页让用户重新登录。
> 更好的方案是 refresh token（短期 access + 长期 refresh），但我没做。

**Q3：怎么实现"强制下线"？**
> JWT 是无状态的，服务端没法直接作废。
> 三种方案：
> ① token 里带 `tokenVersion`，用户表存当前版本，改密码/封号时 +1，版本对不上就失效 —— **最省事**；
> ② 用 Redis 存黑名单（key 是 jti），TTL 设为 token 剩余有效期；
> ③ 缩短 access token 有效期 + refresh token。

**Q4：ThreadLocal 为什么要 remove？**
> Tomcat 用线程池，线程是复用的。
> 如果请求结束不清理，下一个请求复用到这个线程，
> `get()` 会拿到上一个用户的 id → **数据串号**，而且是随机偶发的，极难排查。
> 所以我在拦截器的 `afterCompletion` 里清理（它一定执行，相当于 finally）。

**Q5：拦截器、过滤器、AOP 有什么区别？**
> - Filter 在 Servlet 容器层，最外层，拿不到"要调哪个 Controller 方法"；
> - Interceptor 在 Spring MVC 层，能拿到 handler，适合鉴权、日志；
> - AOP 在 Bean 方法层，按方法签名匹配，适合事务、审计字段填充。
>
> 我的项目里三个都用了：Filter 没用上（可以加 CORS/编码），
> Interceptor 做 JWT 校验和请求日志，AOP 做自动填充。

### 事务

**Q6：`@Transactional` 什么情况会失效？**
> ① **同类内部调用**（`this.method()`）—— 事务靠代理实现，this 调用绕过代理；
> ② 方法不是 `public`；
> ③ 异常被 catch 了没重新抛；
> ④ 异常类型不匹配（默认只回滚 RuntimeException）；
> ⑤ 事务方法里开了新线程。

**Q7：事务的隔离级别？**
> MySQL InnoDB 默认是 **RR（可重复读）**，通过 MVCC + 间隙锁解决幻读。
> 我的项目没改默认级别，因为业务冲突不激烈。

**Q8：为什么加 `rollbackFor = Exception.class`？**
> Spring 默认只回滚 `RuntimeException` 和 `Error`。
> 受检异常（比如 `IOException`）默认**不回滚**，可能留下半截数据。
> 加上它之后任何异常都回滚，更保险。

### 数据库

**Q9：表是怎么设计的？**
> 四张表：
> - `cube_record`：成绩（user_id、time_ms、create_time、update_time、create_user、update_user）
> - `cube_scramble`：打乱公式（record_id 外键 + `ON DELETE CASCADE`）
> - `user`：用户（username 唯一索引 + BCrypt 密码）
> - `daily_stat`：每日统计（`uk_date_user` 唯一键保证幂等）

**Q10：索引建在哪？为什么？**
> - `cube_record.user_id`：所有查询都按用户过滤，必须走索引；
> - `user.username` 唯一索引：保证唯一性 + 登录查询；
> - `daily_stat(stat_date, user_id)` 联合唯一索引：定时任务重复执行时幂等。

**Q11：为什么用 `ON DELETE CASCADE`？**
> 删成绩时，它的打乱公式就没有意义了。
> CASCADE 让数据库自动清理，业务代码一行不用改，也不会留下孤儿数据。

**Q12：用户名重复怎么保证唯一？**
> **应用层先查 + 数据库唯一索引兜底**。
> 只靠应用层查有并发问题：两个请求同时查都说不存在，然后都插入成功。
> 所以最终靠唯一索引拦，捕获 `DuplicateKeyException` 转成业务异常。

### 缓存

**Q13：缓存穿透 / 击穿 / 雪崩怎么处理？**
> - **穿透**（查不存在的数据）：可以缓存空值（短 TTL）或布隆过滤器。我的场景是统计接口，不存在"查不存在的数据"，暂时没做。
> - **击穿**（热点 key 过期瞬间大量请求打库）：可以加互斥锁，只让一个线程去查库。我没做，因为 TTL 60 秒且数据量小。
> - **雪崩**（大量 key 同时过期）：TTL 加随机值。我的 key 就一个，也不会雪崩。

**加分**：能说出"我的场景不需要"比硬讲一堆方案好。

**Q14：缓存一致性怎么保证？**
> 用的是 **Cache Aside + 写时删除**：
> 读的时候先查缓存，没有就查库并回填；
> 写操作成功后**直接删除缓存**（不是更新），下次读自然重建。
>
> 为什么删除而不是更新？因为更新要算新值，可能算错；删除更简单，下次读时自然重建。

### 其他

**Q15：PageHelper 的原理？**
> 它是一个 **MyBatis 拦截器**。
> `PageHelper.startPage()` 把分页参数放进 **ThreadLocal**，
> 拦截器在执行第一条 SQL 时取走参数、清空，
> 然后改写 SQL 加上 `limit`，并额外跑一次 `count`。
> **所以 `startPage` 必须紧跟目标查询**，中间插别的查询会把参数抢走。

**Q16：WebSocket 和 HTTP 轮询的区别？**
> HTTP 是短连接、请求-响应，服务器不能主动说话，想问只能反复轮询（浪费资源、有延迟）。
> WebSocket 是一次 HTTP 握手升级成长连接，之后双向通信，服务器有新消息可以立刻推。
> 电商的"来单提醒"、IM 聊天都是这个场景。

**Q17：文件上传怎么防攻击？**
> ① **UUID 重命名** —— 不用用户提供的文件名，防路径穿越（`../../etc/passwd`）和同名覆盖；
> ② **扩展名 + Content-Type 双白名单** —— 只允许图片；
> ③ **大小限制** —— `spring.servlet.multipart.max-file-size=5MB`；
> ④ **存储目录不在 Web 根目录**，通过静态资源映射访问。

**Q18：怎么保证接口安全？**
> - 鉴权：JWT + 拦截器
> - 数据隔离：SQL 带 user_id
> - 参数校验：`@Valid` + JSR-303
> - 防注入：MyBatis `#{}` 预编译（不用 `${}`）
> - 密码：BCrypt
> - 错误信息：不暴露类名/堆栈（统一"系统繁忙"）
> - 接口文档：生产环境关闭

**Q19：为什么用 springdoc 而不是 Swagger/knife4j？**
> 因为项目用 Spring Boot 4，springdoc 3.0 是配套版本，Knife4j 基于 springdoc 2.x 不兼容。
> 这是 Boot 4 太新的代价 —— 很多第三方 starter 还没跟上。

**Q20：项目有什么不足？**
> 诚实地说几个：
> ① 没有 Spring Security 完整集成，鉴权是自己写拦截器实现的（够用但不完整）；
> ② JWT 没有 refresh token，2 小时后要重新登录；
> ③ 缓存只做了统计接口，没有做防穿透/击穿；
> ④ 没有 Docker 化部署，现在是一键脚本方式；
> ⑤ 单元测试覆盖率不高，主要覆盖核心算法。

**这题必须准备** —— 面试官常问，说"没有不足"是最差的回答。

## 六、踩过的坑（展示深度，挑 3 个讲）

### 坑 1：`@Transactional` 写完没生效

> 一开始我把注解加在一个私有方法上，完全不生效。
> 后来才想明白：Spring 事务是**基于代理**的，只有通过代理对象调用才生效。
> 私有方法、同类内部 `this.` 调用都绕过代理。

### 坑 2：Lombok 的 `@NonNull` 和 Jakarta 的 `@NotNull` 搞混了

> DTO 上我用了 `lombok.NonNull`，结果 Jackson 反序列化直接报
> `Cannot construct instance ... id is marked non-null but is null`。
> 原因是 `@Data` 里含 `@RequiredArgsConstructor`，它把 `@NonNull` 字段当成**必需构造参数**，
> 挤掉了无参构造器，Jackson 只能用那个带参构造器传 null。
> **结论：DTO 上的校验注解一律用 `jakarta.validation.constraints.*`。**

### 坑 3：MyBatis XML 里 `<` 没转义

> 写 `where create_time < #{before}` 导致应用启不来，报 XML 解析错误。
> XML 里 `<` 和 `&` 必须转义成 `&lt;` / `&amp;`（`>` 可以但不建议）。
> 后来我养成了一个习惯：写完 XML 用 `grep -nE '<[[:space:]]'` 自检一遍。

### 坑 4（可选）：多模块后启动方式变了

> 拆成多模块后 `cd server && mvn spring-boot:run` 会失败，因为 common/pojo 没 install 到本地仓库。
> 正确做法是 `mvn -pl server -am spring-boot:run`（`-am` 会连带构建依赖）或直接跑 jar。
