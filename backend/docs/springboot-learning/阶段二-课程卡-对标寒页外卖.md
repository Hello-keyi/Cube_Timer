## D16 · 事务 `@Transactional`

| 项 | 内容 |
|---|---|
| 目标 | 理解"一个业务动作 = 一个事务"；`@Transactional` 生效条件与失效场景 |
| 寒页对照 | 下单：`orders` + `order_detail` 两张表要一起成功；新增菜品 + 口味。寒页**没写注解**，这是它不规范的地方 |
| 预答 3 题 | ① 两条 insert 为什么需要事务？② `@Transactional` 默认回滚哪些异常？③ 为什么同类内部调用 `this.method()` 事务会失效？ |
| 动手任务 | 1) 新增 `POST /record/full`：`{timeMs, scrambles[]}`，成绩+打乱一次写入<br>2) Service 方法加 `@Transactional(rollbackFor = Exception.class)`<br>3) 人为让第 2 条打乱插入失败（如超长/抛异常），验证成绩也回滚<br>4) 去掉注解再跑一次，对比数据库残留（脏数据）<br>5) 记录两种结果的 SQL count |
| 验收 | `POST /record/full` 成功时两表都有数据；故障注入时两表都没有；`select count(*)` 前后一致 |
| 常见坑 | 同类自调用失效；方法非 public；异常被 catch 后没重新抛；默认只回滚 `RuntimeException`；事务里做远程调用/发消息 |
| 时间 | 1 天 |

## D17 · 用户体系 + 密码加密

| 项 | 内容 |
|---|---|
| 目标 | 用户表设计、密码不能明文、BCrypt 加盐校验、唯一性约束 |
| 寒页对照 | `employee` 表（员工）、`user` 表（微信用户）；`EmployeeServiceImpl.login` 校验密码 + 状态 |
| 预答 3 题 | ① 密码为什么不能明文/MD5？② BCrypt 的"盐"解决了什么？③ 注册时如何防止用户名重复（两种做法）？ |
| 动手任务 | 1) 建 `user` 表：`id, username(唯一), password, nickname, status, create_time`<br>2) `POST /user/register`：校验用户名/密码 → BCrypt 加密 → 入库；重复用户名返回业务错误<br>3) `POST /user/login`：查用户 → `BCryptPasswordEncoder.matches()` → 先返回假 token（D18 换真 JWT）<br>4) 用 curl 验证：库里是密文、错误密码失败、重复注册失败 |
| 验收 | `select password from user` 是 `$2a$...`；重复注册 code=1；错误密码 code=1 |
| 常见坑 | 把密码字段放进 VO 返回；用 `@Data` 的 toString 打印密码；多线程下 BCrypt 性能（够用即可） |
| 时间 | 1 天 |

## D18 · JWT + 拦截器 + ThreadLocal（**最重要的一课**）

| 项 | 内容 |
|---|---|
| 目标 | 无状态认证全链路：登录发 token → 请求头校验 → 解析出 userId → ThreadLocal → Service 使用 → 响应后清理 |
| 寒页对照 | `JwtUtil` / `JwtProperties` / `JwtClaimsConstant` / `JwtTokenAdminInterceptor` / `JwtTokenUserInterceptor` / `BaseContext` / `WebMvcConfiguration` |
| 预答 3 题 | ① JWT 三段分别是什么？为什么改 payload 会失效？② 无状态 vs Session 的优缺点？③ 为什么用 ThreadLocal 存 userId，而不是每个方法传参？不用时要 remove 吗？ |
| 动手任务 | 1) pom 加 `jjwt-api/impl/jackson`；`JwtProperties` 配 secret/ttl/tokenName<br>2) 写 `JwtUtil.createJWT/parseJWT`（照寒页签名）<br>3) 登录成功返回 `{token}`；claims 放 `userId`<br>4) 写 `JwtTokenUserInterceptor`：取 `Authorization: Bearer <token>` → 校验 → `BaseContext.setCurrentId(userId)` → 放行；失败 401 JSON<br>5) `WebMvcConfiguration` 注册：拦截 `/record/**`，排除 `/user/login`、`/user/register`、`/doc.html`、`/error`<br>6) `afterCompletion` 里 `BaseContext.removeCurrentId()`<br>7) 成绩表加 `user_id`；Mapper 查询按当前用户过滤；新增成绩写 `user_id` |
| 验收 | 不带 token → 401；错误 token → 401；正确 token → 200；A 用户看不到 B 的成绩；日志里能看到 ThreadLocal 清理 |
| 常见坑 | secret 太短（≥32 字节）；token 前缀没去掉 `Bearer `；拦截路径漏排除导致登录也被拦；ThreadLocal 不清理导致串号；拦截器里抛异常 vs 直接写 401 |
| 交付 | **交付⑤ 登录鉴权体系** |
| 时间 | 1.5 天 |

## D19 · AOP 公共字段自动填充

| 项 | 内容 |
|---|---|
| 目标 | AOP 切面 + 自定义注解 + 反射赋值；把"每个 Service 手写时间/用户"变成一次性机制 |
| 寒页对照 | `aspect/AutoFillAspect`、`annotation/AutoFill`、`enumeration/OperationType`、`constant/AutoFillConstant`；字段 `create_time/update_time/create_user/update_user` |
| 预答 3 题 | ① `@Aspect`/`@Pointcut`/`@Before` 各是什么？② 为什么用自定义注解而不是按包名切（`execution(* ...mapper.*(..))`）？③ 反射赋值的性能与适用边界？ |
| 动手任务 | 1) 表加 4 个公共字段<br>2) 写 `@AutoFill(OperationType.INSERT/UPDATE)` 注解 + 枚举<br>3) 写切面：`@Pointcut("execution(* ...mapper.*.*(..)) && @annotation(AutoFill)")`，反射给实体赋 `now` 和 `BaseContext.getCurrentId()`<br>4) Mapper 的 insert/update 方法加注解<br>5) 验证 INSERT 填全 4 个、UPDATE 只更新 2 个 |
| 验收 | 新增后 SQL 里 `create_user`=当前用户、`create_time` 有值；更新后 `update_*` 变化、`create_*` 不变 |
| 常见坑 | 切点只对 mapper 生效（寒页做法）；参数不是实体时 NPE；字段名用常量别硬编码；INSERT 时 ThreadLocal 还没设置（注册接口）要特判 |
| 时间 | 1 天 |
