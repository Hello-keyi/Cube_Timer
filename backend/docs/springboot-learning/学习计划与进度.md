## 2. 项目定位与角色分工

| 维度 | 后端（主线，80% 投入） | 前端（辅助，20% 投入） |
|---|---|---|
| 目标 | 成为核心能力，面试和工作主要看它 | 只求"能用"，不追求前端工程化深度 |
| 谁定义接口 | **后端定义**：路径、参数、返回结构、错误码 | 前端照抄，不擅自改结构 |
| 业务计算放哪 | **统计、校验、业务规则全放后端** | 前端只做"展示格式转换" |
| 学习方式 | 每个知识点**手写** | 能读懂、能改、能自己加个小功能 |

### 2.1 "前端按后端逻辑思考"的具体含义

这是本项目最重要的原则，三条：

1. **契约先行**：后端先想清楚「这个方法叫什么、吃什么参数、吐出什么结构」，写进「4. 接口契约」，前端照着写。
2. **业务规则在后端**：比如 "AVG5 要去掉最好和最差" 属于业务规则 → 后端算，前端只显示。目前它在前端 `utils/format.js` 里算，D12 会搬到后端。
3. **前端校验不可信**：后端必须自己校验（D4/D9）。前端的校验只是为了体验好，绕过它只要一条 curl。

> **判断标准**：如果这段逻辑"换个前端（小程序/App/命令行）还得有"，那它就该在后端。

### 2.2 「自己写」和「抄实例」怎么分（学习法核心）

**结论：不是二选一。按「信息的性质」分三层，各用不同方法。**

| 层 | 是什么 | 本项目典型例子 | 方法 | 为什么 |
|---|---|---|---|---|
| **① 事实层** | 「叫什么 / 有什么 / 语法怎么写」 | `@RestControllerAdvice` 这个注解名；`Result` 有 `code/msg/data`；`limit #{offset}, #{size}` 的写法；`@ExceptionHandler` 的参数类型 | **📋 直接抄**（10 秒） | 这属于「一搜就有」的知识。硬猜 = 浪费 1 小时，且面试不考「你能否背出注解名」 |
| **② 结构层** | 「放在哪 / 谁调谁 / 顺序 / 范围」 | 校验写 Service 还是 Controller？`BusinessException` 放哪个包？异常处理器要接几种？`@ExceptionHandler` 的优先级？ | **🧩 给骨架 + 自己填**（只给方法签名和注释，不给实现） | 这是「设计判断」，必须自己过一遍脑子；抄了等于没学 |
| **③ 应用层** | 「针对自己业务的实现」 | `timeMs` 上限设多少？提示语文案？哪几种输入算非法？成绩要不要去重？ | **✍️ 必须自己写**，一个字别抄 | 这是唯一「属于你」的部分，也是面试和答辩能讲的 |

**一把尺子（判断某个东西该抄还是该写）：**

> **忘掉它之后，你能在 5 分钟内靠搜索 / 官方文档找回来吗？**
> - 能 → 📋 抄（事实层）
> - 不能 → 🧩 / ✍️ 必须自己想（结构层、应用层）

**抄写三条铁律：**

1. **抄完必须默写**：关掉参考，新建文件重写一遍。写不出来 = 没学会，回去补。
2. **抄的每一行必须能解释**：能用自己的话注释出来，否则删掉重写。
3. **报错先自查 10 分钟**：报错是最好的老师。AI 只告诉你「往哪看」，不直接给改好的代码。

**要避免的两种极端：**

| 极端 | 表现 | 后果 |
|---|---|---|
| 全靠自己摸索 | 从零去猜 `@RestControllerAdvice` 这个名字 | 1 小时猜不出来，挫败放弃 |
| 全靠抄 | 抄完能跑，关掉参考就写不出 | 换个需求就废，面试讲不清 |

## 3. 架构与数据流

### 3.1 当前链路（已完成部分）

```
浏览器 (localhost:5173)
   │  前端 Vue：TimerDisplay 计时 → useRecords.add(timeMs)
   ▼
api/records.js   →   fetch('/api/record?timeMs=12345', { method:'POST' })
   │
   ▼  Vite 代理：/api/*  →  http://localhost:8081/*
后端 Spring Boot (localhost:8081)
   │
   ▼
CubeRecordController      @RestController  @RequestMapping("/record")
   │   参数绑定：@RequestParam Integer timeMs
   ▼
CubeRecordService         （接口，只有声明）
   │
   ▼
CubeRecordServiceImpl     @Service，@Autowired Mapper；组装 Entity
   │
   ▼
CubeRecordMapper          @Mapper 接口，@Insert 注解写 SQL
   │   MyBatis 动态代理：把方法调用翻译成 SQL
   ▼
MySQL  cube_timer.cube_record
```

**返回方向反过来：** MySQL 行 → MyBatis 映射成 `CubeRecord`（靠 `map-underscore-to-camel-case`）→ Service 原样返回 → Controller 返回 → Jackson 序列化成 JSON → 前端 `res.json()`。

### 3.2 目标架构（15 天后）

```
Controller  只负责：路由、参数绑定、调 Service、包 Result
    ↓
Service     负责：业务规则、校验、事务、缓存、编排多个 Mapper
    ↓
Mapper      只负责：SQL
```

新增的横切能力：
- `common/Result.java`：统一返回
- `exception/` + `handler/`：业务异常 + 全局异常处理
- `dto/` + `vo/`：入参/出参对象
- 分页、动态 SQL、聚合统计、Redis 缓存、拦截器

### 4.3 数据库现状

```sql
CREATE DATABASE cube_timer DEFAULT CHARACTER SET utf8mb4;

CREATE TABLE cube_record (
  id         INT PRIMARY KEY AUTO_INCREMENT,
  time_ms    INT NOT NULL COMMENT '成绩，单位毫秒',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

> **设计决策**：成绩存**整数毫秒**，不存小数秒。原因：整数计算/排序/求平均无精度问题；前端展示时再 `/1000`。

## 6. 数据库设计（现状 + 规划）

```sql
-- 现状
cube_record (id, time_ms, created_at)

-- D11 规划：一条成绩对应一串打乱公式（一对多）
cube_scramble (
  id        INT PK AUTO_INCREMENT,
  record_id INT NOT NULL,        -- 关联 cube_record.id
  scramble  VARCHAR(255) NOT NULL,  -- 例如 "R U R' U' F2 D L2"
  seq       INT NOT NULL         -- 第几条（一次复原可能有多段）
)
```

> D11 要讲清：为什么关系放 `cube_scramble.record_id` 而不是在 `cube_record` 里存一串？—— 因为关系型数据库一个格子存不了一个列表。

## 11. 易错清单（30+ 条，最值钱的一节）

**框架/版本**
- Spring Boot 4 与 3.x 包名、starter 名不同；照 3.x 教程抄会报错
- 本项目 starter 是 `spring-boot-starter-webmvc`（不是 `-web`）
- `@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)` 会让数据库配置完全失效

**参数绑定**
- `@RequestParam`（URL 参数）/ `@PathVariable`（路径里的）/ `@RequestBody`（JSON 体）三者别混
- 多参数 Mapper 方法必须加 `@Param`，否则 `Parameter 'xxx' not found`

**MyBatis**
- `#{}` 预编译占位符（安全）；`${}` 字符串拼接（SQL 注入风险）
- `namespace` + `id` 必须和接口全名 + 方法名完全一致，否则 `Invalid bound statement`
- `map-underscore-to-camel-case: true` 没配 → 对象字段全 null
- XML 里 `<` 要写成 `&lt;`

**分层**
- Entity 不要直接当接口入参/出参
- `BeanUtils.copyProperties` 只复制同名同类型，类型不同静默跳过
- Controller 不写业务逻辑、不写 try-catch
- Service 方法 = 一个业务动作，可以调多个 Mapper

**运行/调试**
- 改 Java 代码必须重启后端；改前端代码 Vite 热更新
- 控制台 `==> Preparing:` 是第一手证据，报错先看它
- 端口冲突：8081 被占 → 改端口
- **方法重载（overload）**：同名方法靠「参数个数或类型不同」共存；`success()` 与 `success(T data)` 就是重载
- **HTTP 里传的永远是文本**：返回结构从 `[...]` 变成 `{code,data}`，变的是「JSON 的形状」，不是「变成 JSON」
- 改了返回结构**必须同步前端**，否则前端把对象当数组用 → `TypeError: xxx.slice is not a function`

### 15.5 MySQL 不会自启（已踩 3 次）及永久解法

**症状**：所有接口都返回 `{"code":1,"msg":"系统繁忙"}`；
控制台第一条异常是 `CannotGetJdbcConnectionException: Failed to obtain JDBC Connection`。

**已发生**：2026-10-27、2026-11-01、2026-11-03（每次都是 WSL 重启后）

**方案 A（立刻，每次手动）**
```bash
sudo service mysql start
sudo service mysql status
```

**方案 B（一劳永逸：给 WSL 开启 systemd）**

1. WSL 里编辑（需 sudo）：`sudo nano /etc/wsl.conf`，改为：
```ini
[user]
default = yi

[boot]
systemd=true
```
2. Windows PowerShell 里执行（先关掉所有 WSL 窗口）：
```powershell
wsl --shutdown
```
3. 重开 WSL，确认 PID 1 变成 systemd：
```bash
ps -p 1 -o comm=       # 应输出 systemd
```
4. 让 MySQL 开机自启（只需一次）：
```bash
sudo systemctl enable mysql
```
5. 以后查状态用：`sudo systemctl status mysql`

**当前环境实测（2026-11-03）**
- `ps -p 1 -o comm=` → `init(Ubuntu-22.04)`（**不是 systemd**）
- `/etc/wsl.conf` 只有 `[user] default = yi`，没有 `[boot] systemd=true`
- 结论：**systemd 未开启 → 服务不会自启**，所以每次 WSL 重启后要手动起 MySQL
